# БРЕД

**Б**ыстрая **Р**етрансляция **Э**лектронных **Д**анных — мессенджер в духе
Дискорда, который работает без собственного сервера.

Узлы находят друг друга сами: в локальной сети — по UDP-маячку, в интернете —
через пробивку NAT. Сообщения едут напрямую между участниками и хранятся у них
же. Наших серверов в схеме нет вообще: нечего оплачивать, нечего взламывать,
нечего отключать.

```
┌──────────────────────────────────────────────────────────────┐
│ БРЕД   Орбита*   Дизайн-цех                    сеть: p2p     │
├────────────┬────────────────────────────────┬────────────────┤
│ КАНАЛЫ  08 │ #общий-канал        142 online │ УЧАСТНИКИ  142 │
│            │                                │                │
│ общее ──── │ 02.08.2026 ──────────────────  │ online 4 ───   │
│ #общий     │ марина ковач        14:02:04   │ ● марина  voc  │
│ #ссылки    │ Ребят, кто трогал новый…       │ ● тимур   typ  │
│ #мемы   12 │                                │ ● аня      on  │
│            │ тимур лаас          14:03:41   │                │
│ голос ──── │ │ ─────────────────────────    │ offline 2 ──   │
│ > стендап  │ │ window.addEventListener(…)   │ ○ влад     2ч  │
│            │ │ ─────────────────────────    │ ○ юля      1д  │
├────────────┴────────────────────────────────┴────────────────┤
│ kaneu@Орбита ❯ сообщение или /команда              █  0/2000 │
├──────────────────────────────────────────────────────────────┤
│ — ВВОД — │ #общий-канал │ 4 online │ ^K ввод · ⏎ отправить   │
└──────────────────────────────────────────────────────────────┘
```

Интерфейс — монохромный терминал: ни одного цветового акцента, иерархия держится
на весе, инверсии и пустоте.

## Запуск

Нужны Rust 1.82+, Node 20+ и pnpm.

```bash
pnpm install
pnpm tauri dev      # разработка
pnpm tauri build    # сборка под текущую ОС
```

Windows и macOS собираются из одного исходника; под Windows дополнительно нужен
WebView2 (есть в системе начиная с Windows 11).

## Как этим пользоваться

Регистрации нет. При первом запуске создаётся ключ устройства — он и есть ваша
личность.

Всё делается из той же строки ввода, что и сообщения:

| Команда | Что делает |
|---|---|
| `/простор Орбита` | создать пространство (аналог сервера) |
| `/канал баги` | создать канал в текущем пространстве |
| `/позвать` | скопировать ссылку-приглашение в буфер |
| `/войти bred://join/…` | войти по чужой ссылке |
| `/имя тимур` | сменить отображаемое имя |
| `/голос стендап` | создать голосовой канал |
| `/звонок стендап` | войти в звонок |
| `/файл` | выбрать файлы и прикрепить к сообщению |
| `/аватар` | поставить картинку профиля (можно GIF) |
| `/экран` | включить или убрать демонстрацию экрана |
| `/покинуть` | выйти из пространства и стереть его историю |
| `/лс имя` | открыть личную переписку (или клик по участнику) |
| `/эмодзи имя` | добавить свой эмодзи, доступен как `:имя:` |
| `/стикер имя` | добавить стикер: показывается крупно |

Клик по голосовому каналу — вход в звонок. Файлы прикрепляются кнопкой `+`
слева от строки ввода; получатель качает их одним кликом прямо из ленты.

Горячие клавиши: `^K` — фокус на ввод, `^U` — прикрепить файл, `^I` —
приглашение, `^1`…`^9` — каналы, `^D` — микрофон, `^E` — выйти из звонка,
`↑`/`↓` — история отправленного, `Esc` — закрыть ветку или отменить ответ.

Несколько профилей на одной машине — через `BRED_DATA_DIR`:

```bash
BRED_DATA_DIR=/tmp/бред-1 pnpm tauri dev
BRED_DATA_DIR=/tmp/бред-2 pnpm tauri dev
```

## Что уже работает

- пространства, категории, текстовые и голосовые каналы;
- сообщения, ответы с цитатой, правка, удаление, реакции, счётчики веток;
- непрочитанное по каналам и пространствам;
- присутствие «в сети» и индикатор «печатает»;
- история переживает перезапуск и **догоняется от пиров** после офлайна;
- обнаружение в локальной сети без какой-либо инфраструктуры;
- **групповые звонки** — голос и видео, полная сетка соединений, без сигнального
  сервера и без STUN/TURN;
- **передача файлов** — напрямую между устройствами, с проверкой целостности и
  докачкой после обрыва;
- превью картинок и GIF прямо в ленте, аватары профилей;
- эмодзи-пикер для реакций и сообщений;
- ветки: и чтение, и запись;
- демонстрация экрана отдельной дорожкой, вместе с камерой;
- уведомления ОС, когда окно в фоне;
- пагинация ленты вверх по курсору;
- сборка мусора: файлы без ссылок удаляются;
- сквозное шифрование: всё, что уходит в сеть, зашифровано ключом пространства,
  каждое событие подписано автором.

## Как устроены звонки

Комната звонка — это голосовой канал. Сигнального сервера нет: кто находится в
канале, и так видно по присутствию, которое разлетается по gossip.

Захват и кодирование (Opus для звука, VP8 для видео) делает вебвью — оттуда же
приезжает системное эхоподавление и шумодав. Транспорт свой: закодированные
куски уходят в ядро и дальше QUIC-датаграммами через уже пробитое iroh
соединение. **WebRTC не используется намеренно** — он потребовал бы STUN/TURN,
то есть внешние серверы.

Топология — полная сетка: каждый шлёт поток каждому. Для 4–6 человек это лучший
вариант (нет микшера, минимальная задержка), дальше упирается в исходящий канал.
Звонки на десятки человек потребуют SFU, а SFU — это сервер.

## Чего пока нет

Роли и модерация, личные сообщения, поиск по истории, уведомления ОС, запись
звонка и демонстрация экрана. Порядок работ — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Дискорд и БРЕД: что есть, чего нет

Сравнение по состоянию на текущую версию. «Частично» означает, что механика
работает, но обвязки меньше, чем в Дискорде.

### Переписка

| Возможность | Дискорд | БРЕД |
|---|---|---|
| Текстовые каналы, категории | есть | есть |
| Ответ с цитатой | есть | есть |
| Правка и удаление | есть | есть |
| Реакции | есть, с пикером и своими эмодзи | частично: пикер есть, своих эмодзи нет |
| Ветки обсуждения | есть | есть: панель ветки, чтение и запись |
| Markdown | полный | частично: блоки кода |
| Упоминания `@` и роли в тексте | есть | нет |
| Закреплённые сообщения | есть | нет |
| Поиск по истории | есть | нет |
| Форумы, анонсы, события | есть | нет |

### Файлы и медиа

| Возможность | Дискорд | БРЕД |
|---|---|---|
| Вложения в сообщениях | есть, через серверы | есть, напрямую между устройствами |
| Предел размера | 10 МБ бесплатно, 500 МБ с Nitro | 512 МБ, упирается только в диск |
| Докачка после обрыва | нет | есть |
| Проверка целостности | нет отдельно | есть, blake3 по содержимому |
| Превью картинок в ленте | есть | есть, включая GIF |
| Стикеры, GIF, свои эмодзи | есть | есть |

### Звонки

| Возможность | Дискорд | БРЕД |
|---|---|---|
| Голосовые каналы | есть | есть |
| Видео | есть | есть |
| Групповые звонки | десятки участников через свои серверы | есть, сетка; комфортно 4–6 человек |
| Эхоподавление, шумодав | есть | есть, системное |
| Демонстрация экрана | есть | есть, отдельной дорожкой |
| Push-to-talk | есть | частично: только выключение микрофона |
| Трансляции, запись | есть | нет |
| Шифрование медиа | E2EE для звонков | E2EE всегда |

### Структура и люди

| Возможность | Дискорд | БРЕД |
|---|---|---|
| Серверы и приглашения | есть | есть: пространства и ссылка с ключом |
| Присутствие, «печатает» | есть | есть |
| Личные сообщения | есть | есть, ключ выводится без приглашения |
| Роли и права | есть | нет |
| Модерация: бан, кик, таймаут | есть | нет и не будет в привычном виде — некому исполнять решение |
| Профиль, аватар | есть | есть, аватар может быть GIF |

| Уведомления ОС | есть | есть |

### Инфраструктура и приватность

| | Дискорд | БРЕД |
|---|---|---|
| Нужен аккаунт | да | нет, личность — ключ на устройстве |
| Где лежит история | на серверах Дискорда | у участников |
| Сквозное шифрование текста | нет | есть |
| Работа в локальной сети без интернета | нет | есть |
| Чтение истории офлайн | ограниченно | полностью |
| Стоимость инфраструктуры | платит Дискорд | ноль |
| Можно отключить централизованно | да | нет |
| Модерация контента платформой | есть | нет — со всеми последствиями |
| Размер клиента | сотни мегабайт | около 15 МБ |

### Где Дискорд объективно лучше

Большие сообщества, модерация, экосистема ботов, поиск по годам переписки,
превью и эмодзи, звонки на сотню человек. Всё это либо требует сервера, либо
просто ещё не написано.

### Где лучше БРЕД

Работа без интернета и без чужой инфраструктуры, отсутствие регистрации,
сквозное шифрование всего, история в собственных руках, вес клиента. Плюс то,
чего у централизованного сервиса быть не может: его нельзя отключить, продать
или закрыть.

## Честно о модели безопасности

- Пространство — это симметричный ключ. **Кто знает ключ, тот участник.** Отозвать
  доступ у того, кому вы уже дали ссылку, без ротации ключа нельзя; ротации пока
  нет.
- Релеи n0 используются только когда не удалось соединиться напрямую. Содержимое
  им недоступно, но факт соединения между двумя адресами — виден.
- История пространства целиком лежит у каждого участника. Для команды это
  нормально, для сообщества в десятки тысяч человек — нет.
- Файлы раздаёт любой, у кого они есть, а не только автор. Это делает загрузку
  надёжнее, но означает, что удалить отправленный файл «у всех» нельзя.

## Разработка

```bash
cargo test                 # 60 тестов
cargo clippy --all-targets # без предупреждений
cargo fmt
pnpm check                 # svelte-check
```

Ключевые тесты:

- `tests/convergence.rs` — два узла пишут одновременно, обмениваются событиями и
  обязаны прийти к дословно одинаковой ленте; повторная доставка безвредна,
  подделанная подпись отвергается;
- `tests/transfer.rs` — файл доезжает побайтово, докачка после обрыва даёт тот же
  результат, чужак без ключа пространства не получает ничего;
- `net::media` — сборка кадра из фрагментов, устойчивость к дублям, потерям и
  мусорным индексам.

**Что проверено не полностью:** сам захват камеры и микрофона. Транспорт,
фрагментация, комнаты и файлы покрыты тестами, но конвейер WebCodecs требует
живого устройства — его нужно проверить руками на macOS и Windows.

Размер фронтенда: 26.9 КБ JS + 3.1 КБ CSS в gzip, без внешних шрифтов и картинок.
